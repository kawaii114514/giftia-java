# Java 后端迁移说明

迁移日期：2026-11-13 至 2026-11-14。

## 范围与运行入口

默认后端由 `backend/server.py` 切换为 `backend-java/` 的 Spring Boot 应用，使用 Java 17、Spring AI、Spring JDBC 与 SQLite。Java 直接承担模型调用、工作流、长期记忆、用户画像、角色卡、会话存储、认证、限流、SSE 和服务指标，不再需要 Python 进程配合运行。

此次迁移不修改 `frontend/` 源代码，保留现有记忆花园页面、状态管理和调用格式。默认后端为 `127.0.0.1:8000`，前端为 `127.0.0.1:3000`；已有 `/api/...` 与 `/api/v1/...` 路径均保留。Python 源码、依赖说明与测试仍在仓库中，作为参考和必要时的回退入口。

项目根目录的 `start.bat` / `start.sh` 使用 Maven wrapper 打包，然后通过 `java -jar` 运行 Java 后端。首次打包需要下载 Maven 与依赖。Windows 服务使用隐藏的后台进程，日志和 PID 写入 `.run/`；Unix 脚本保持前台运行并在退出时停止自己启动的进程。端口已占用时脚本退出提示，不结束原服务或其他进程。

## 当前工作流

`GiftiaWorkflow` 使用 `CompletableFuture` 与有界线程池固定编排：

1. 读取用户角色，发送状态事件，等待该用户上一轮记忆更新（有超时）。
2. 并行情绪分析与记忆检索，失败或超时时使用降级上下文。
3. 组合固定规则、角色卡、画像、工作摘要、检索记忆、近期历史与必要的早期摘要。
4. Spring AI 调用对话模型，逐 Token 发送 SSE；有效回复先写入会话，再发送完成事件。
5. 后台提取事实、更新工作摘要与画像；同一用户的记忆回写按顺序协调。

这里是 Java 中显式定义的固定工作流，运行时不使用 LangGraph，也没有转发到旧 Python 服务。检索采用多查询、语义/关键词双路召回、RRF 与规则加权重排，不依赖独立的学习型 Reranker 服务。

## 数据路径与兼容

默认沿用以下位置，不要求复制或重建数据库：

| 位置 | 保存内容 |
| --- | --- |
| `backend/giftia.db` | 会话、长期记忆、工作摘要、结构化画像 |
| `backend/character_config.json` | 用户选择的角色与自定义角色卡 |
| `backend/prompt_config.json` | 兼容旧版全局人设配置 |
| 根目录 `.env` | 运行时模型密钥与应用配置；不提交版本库 |

SQLite 使用原有表与 JSON 字段格式，新增所需表使用 `CREATE TABLE IF NOT EXISTS`。角色配置继续使用原文件位置，并以临时文件加替换方式持久化。用户 ID、会话 ID、记忆 ID 不因为切换语言而重新生成。

本次切换前已通过在线备份保留原数据，位置为 `.venv/giftia-run/java-migration-20261113-174739/`。该目录只作为恢复依据保留，不由启动脚本重建或覆盖，也不提交版本库。SQLite 运行于 WAL 模式，后续自行备份应使用一致性备份或先正常停止写入，不能只在运行中任意复制主 `.db` 文件。

### 清空记忆的明确变化

`DELETE /api/memory/{user_id}` 现在在事务中删除该用户的长期记忆、`working_memory` 工作摘要与 `user_profiles` 画像，保留会话和角色配置。旧 Python 接口只删除长期记忆，可能留下摘要和画像；本次将三个记忆表面的清空动作统一。

已排队的旧记忆任务通过用户代次检查丢弃过期写入，避免清空后旧任务重新填入数据。会话文字依然保留，继续发送旧会话时这些文字仍可能作为历史上下文传入模型；如需从空白上下文继续，请新建会话。此操作不等于删除该用户的全部个人数据。

## 配置兼容

Java 运行时读取项目根目录 `.env`，不会要求把真实密钥写进 Java 或 Python 源码。现有提供商变量和独立 `EMBEDDING_API_KEY` 继续支持；`Deepseek_API_KEY`、`ZhipuAI_API_KEY` 旧拼写也保留兼容。

新默认值为对话 `CHAT_MODEL=deepseek-v4-flash` / `CHAT_BASE_URL=https://api.deepseek.com/v1`，向量 `EMBED_MODEL=BAAI/bge-m3` / `EMBED_BASE_URL=https://api.siliconflow.cn/v1/embeddings`。这两组配置彼此独立；变更后重启后端生效。可用 `CHAT_API_KEY` 直接指定对话密钥，或继续按服务商变量匹配。

情绪分析保留原来的 12 种标签。`CHAT_MULTIMODAL=auto` 沿用原视觉模型能力目录，也可设置 `true` / `false` 覆盖自定义接口的能力；`CHAT_THINKING_ENABLED=true` 默认在已支持的 DeepSeek / GLM / Qwen 对话中启用思考，分析和记忆任务始终关闭思考。

`GIFTIA_DATABASE` 可指定数据库绝对路径；默认不设置以沿用原文件。访问密钥、管理员密钥和 CORS 配置维持原语义。管理员密钥未独立设置时回退到访问密钥值，请求头仍使用 `X-Admin-Key`。共享密钥和用户 ID 分区没有扩展为注册登录或租户鉴权系统。

## HTTP 与流式约定

- 保留两套路径前缀、前端 JSON 字段和 `{"detail":"说明"}` 错误结构。
- SSE 保留 `status`、`token`、`reply`、`done`、`error` 类型，帧为 `data: ` 加 JSON 和两个换行。每次事件显式刷新输出，`done` 携带保存后的 `conversation_id`。
- 文本模型不接受非空图片输入；图片类型/编码、10MB 解码上限和历史消息边界在开启 SSE 前校验，返回 422。
- 限流仍为聊天按用户 30 次/分钟、普通请求按 IP 60 次/分钟，作用范围为单个后端进程。
- 日志与指标需要管理员密钥。指标统计真实请求量、错误量、平均耗时及模型调用；不将计数接口描述为已压测的吞吐量结果。
- `/api/health` 为公开健康检查，含模型依赖状态并缓存 30 秒。Java 默认不再提供旧 FastAPI 的 `/docs` 页面。

## 验证

后端在 `backend-java/` 中运行 `mvnw.cmd verify`（Windows）或 `sh ./mvnw verify`（Unix），前端在 `frontend/` 中依次运行 `npm run lint`、`npm run build`、`npm run test`。CI 默认运行 Java 与前端检查；Python 参考实现的原有检查可通过手动工作流选项触发。

自动验证覆盖接口契约、SSE、认证与限流、算法与持久化、角色规则与用户作用域。测试应使用临时数据库、临时配置和模拟模型，不能依赖本机真实 `.env` 或真实用户库。

## 回退参考

需要回退时，先正常停止 Java 服务，确认端口 8000 已释放；不要同时运行两个后端向同一数据文件写入。保留当前数据库和配置的最新备份，再依据具体故障选择仅切换运行时，或从本次切换前的一致性备份恢复。不要直接覆盖运行中的 SQLite 主文件。

旧 Python 运行时需要 Python 3.11+ 和 `requirements.txt`，可在独立虚拟环境安装依赖后，从项目根目录手动运行：

```bash
python -m pip install -r requirements.txt
python -m uvicorn server:app --app-dir backend --host 127.0.0.1 --port 8000
```

旧实现的模型名和接口地址仍由 `backend/model_config.py` 管理，不能假定 Java 新增的模型环境变量会自动改变 Python 配置。前端仍连接同一后端端口。回退不会自动撤销 Java 运行期间合法写入的对话或记忆；恢复备份会丢弃备份时间之后的修改，必须先保留现状。
